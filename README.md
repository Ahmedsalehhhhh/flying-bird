# Flying Bird — Auth

```
flying bird/
├── server/           سيرفر الـ Auth (Express + MongoDB) — يخدم أكتر من لعبة
├── admin-dashboard/  داش بورد الأدمن (React) — فرونت منفصل
├── postman/          كولكشن Postman
└── API.md            شرح الـ endpoints
```

## الفكرة

1. الأدمن بيعمل حساب للاستريمر من الداش بورد (يوزر + باسورد) ويبعتهوله.
2. اللعبة بتبعت `POST /api/login` فيه اليوزر والباسورد والـ `deviceId`.
3. **أول دخول** بيقفل الحساب على الجهاز ده. بعد كده أي جهاز تاني بياخد `WRONG_DEVICE`.
4. اللوجين بيرجّع `token`. السيشن مدتها شهر (`SESSION_DAYS`) وبتتمد شهر من جديد مع كل `/session` أو `/play`، يعني طول ما الاستريمر بيفتح اللعبة مش هيعمل لوجين تاني، ولو فضل شهر مافتحهاش هيعمل لوجين من الأول. كل مرة اللعبة تتفتح بتبعت `GET /api/session` بالتوكن والـ `deviceId` في الهيدر عشان تتأكد إن السيشن لسه شغالة. ولما الاستريمر يدوس PLAY بتبعت `POST /api/play` بنفس الهيدرز.
5. لو الاستريمر غيّر جهازه، الأدمن بيدوس **فك ربط الجهاز**.
6. **الاشتراك:** كل استريمر ليه تاريخ بداية ومدة (من 1 لـ 12 شهر) بيحددهم الأدمن وهو بيعمل الحساب أو من زرار **تجديد الاشتراك**. لو الاشتراك خلص، اللوجين و `/session` و `/play` بيرجعوا `SUBSCRIPTION_EXPIRED`. التجديد من آخر يوم في الاشتراك بيضيف المدة على الأيام الباقية. حسابات الوكالة من غير انتهاء إلا لو الأدمن حدد لها اشتراك.
7. الحساب بيفضل شغال لحد ما اشتراكه يخلص، أو الأدمن يحظره أو يمسحه.

## تشغيل السيرفر

```
npm run setup     (أول مرة بس)
npm start
```

ملف `server/.env` لازم يكون فيه:

- `MONGO_URI`
- `MONGO_DB_NAME`
- `JWT_SECRET`
- `ADMIN_PASSWORD`: باسورد دخول الداش بورد

باقي الإعدادات (`GAMES` (أول مرة بس) و `SESSION_DAYS` و `LOGIN_LOG_DAYS` ...) موجودة في `server/.env.example`.

## اللعب

من الداش بورد، في كارت **"اللعب"**:
- **+ لعبة جديدة:** اكتب الاسم والـ `gameId`. الـ `gameId` هو اللي اللعبة بتبعته في اللوجين ومش بيتغير بعد كده. اللعبة بتشتغل على طول من غير redeploy.
- **تعديل الاسم:** بيغيّر الاسم اللي بيظهر بس.
- **إيقاف:** كل حسابات اللعبة بتتقفل فوراً (`GAME_DISABLED`)، والحسابات والاشتراكات مش بتتمسح. **تشغيل** بيرجّع كل حاجة زي ما كانت.
- **حذف:** بيشتغل بس لو اللعبة مافيهاش حسابات.

`GAMES` في `.env` بقى seed بس: اللعب اللي فيه بتتضاف للداتابيز أول مرة لو مش موجودة.

## حماية اللعبة من الكراك (اختياري)

اللعبة ممكن تبعت `X-Build-Hash` (sha1 أو sha256 بتاع ملف اللعبة نفسه) مع كل ريكويست. من كارت "النسخ المعتمدة" (بيظهر لما تختار لعبة واحدة فوق) تسجّل الـ hash بتاع كل إصدار رسمي.

- **افتراضياً (وضع المراقبة):** أي نسخة مش متسجلة بتتحط كتنبيه على الحساب في جدول الحسابات ("نسخة مش معروفة")، من غير ما تمنع اللاعب.
- **لتفعيل المنع الفعلي:** بعد ما تسجّل كل النسخ الرسمية اللي شغالة، حط `ENFORCE_BUILD_CHECK=true` في إعدادات السيرفر. من ساعتها أي نسخة مش في القايمة هترجّع `BUILD_MISMATCH` ومش هتقدر تلعب.
- **مهم:** مع كل تحديث جديد للعبة، سجّل الـ hash بتاعه الأول قبل ما توزّعه، وإلا كل اللاعبين هياخدوا رفض لو وضع المنع مفعّل.

## الرفع على Hostinger

- **Root directory:** فاضي (أول الـ repo)
- **Entry file:** `server.js`
- **Output directory / Build command:** فاضيين
- **Node.js:** 20 أو 22

`npm install` في أول الـ repo بيسطّب dependencies السيرفر لوحده (`postinstall`)، و `server.js` بيشغّل `server/src/index.js`. الإعدادات (`MONGO_URI` و `JWT_SECRET` ...) بتتحط في Environment variables على Hostinger.

## الداش بورد

السيرفر نفسه بيعرض الداش بورد على `/admin`:

- أونلاين: https://dodgerblue-jackal-575473.hostingersite.com/admin
- على جهازك: http://localhost:3000/admin

الصفحة دي ملف جاهز في `server/public/index.html`. لو عدّلت في كود الداش بورد، اعمل build تاني:

```
cd admin-dashboard
npm install          (أول مرة بس)
npm run build:server
```

وبعدين push و redeploy.

## Postman

1. اعمل Import لملف `postman/Flying-Bird-Auth.postman_collection.json`.
2. في تاب **Variables** حط `adminPassword`، ولو هتجرب على السيرفر الأونلاين غيّر `baseUrl`.
3. شغّل الطلبات بالترتيب من 1 لـ 21 (فيهم 20a–20e بتجرب الاشتراك المنتهي والتجديد)، أو دوس Run collection. التوكنات والـ `userId` بيتحفظوا لوحدهم.

### كل حالات الاشتراك والسيشن

ملف `postman/Flying-Bird-Subscriptions-Session.postman_collection.json` فيه كل حالة لكل request جديد أو متعدّل، ومع كل request مثال بالرد الحقيقي.
- حط `adminPassword` في الـ Variables، وغيّر `baseUrl` لو هتجرب أونلاين، وبعدين دوس Run collection.
- الكولكشن بيعمل حسابات تجريبية لوحده (أولها `runId` عشوائي) وبيمسحها في الآخر.
- الطلبات اللي عليها **[reference]** مش بتتبعت لما تشغّل الكولكشن، لأنها حالات صعب تتعمل من Postman (زي 30 يوم من غير نشاط). افتح المثال بتاعها عشان تشوف الرد.
